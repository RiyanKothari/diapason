01 · Run a test

Point it at an agent. Press run.

Diapason's own reference agents run free, so you can watch v1's planted bugs get caught and v4 pass. Your agent connects over the stream your phone platform already speaks.

Most voice stacks already take phone calls over a media stream: pick the platform yours runs on (Twilio, Exotel or Plivo) and paste that websocket URL. Otherwise the Diapason protocol is four messages: a JSON start, binary PCM both ways, and optional clear / hangup. Live calls use Timbre voices and Prisma ears, capped by the budgets above.

03 · v1 → v4

Planted bugs, caught, then gone

Each later version removes them a different way: a better prompt, code that checks every line before it's spoken, secrets kept out of the model's reach, and finally a model that only picks what to do while code says it. 05 · Suite writer

Your SOP in, an attack suite out

Every rule in the SOP gets a caller built to tempt the agent into breaking it, sounding like your real callers if you paste a few of their lines. Rules no caller can test are named, not hidden. Uses Evon.

06 · Shield

Compliance on live calls, no code change

Point your Twilio, Exotel or Plivo stream at diapason shield --agent <its url>. Monitor flags every line that breaks the rules; block holds each line until it's checked and replaces a violation with a safe line.
